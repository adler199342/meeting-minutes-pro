# 会议纪要编辑规则

## 一、先识别会议任务

- 决策会：突出选择、依据、边界、责任人。
- 汇报会：突出成果、关键指标、差距、下一阶段。
- 项目推进会：突出进展、阻塞、依赖、里程碑。
- 培训宣讲会：突出核心主张、知识框架、案例、要求。
- 复盘会：突出目标、结果、偏差、原因、改进。
- 交流会：选择最接近的主类型，不使用流水账。

据此填写 `summary_layout`。不要因为原文有时间戳就默认使用时间线。

## 二、顶部总结的编辑顺序

按以下问题筛选内容，而不是把正文缩短后复制到顶部：

1. 最终定调是什么？
2. 哪些决定已经成立？
3. 哪些数字改变了判断？
4. 最大分歧、风险或阻塞是什么？
5. 接下来谁做什么？

`executive_summary` 写成一条管理判断，25–65 个中文字符。删除“会议讨论了”“双方交流了”等过程性语言。

## 三、事实—判断—含义—行动

每个重要结论至少区分两层：

- 事实：原文明确出现的数据、事件、案例或表态。
- 判断：事实支持的会议结论。
- 管理含义：该结论对指标、流程、岗位、资源或风险意味着什么。
- 行动：明确责任人与完成标准。

不要把归纳判断写成参会人原话。`meeting_analysis` 必须是基于会议内容的归纳，不得补充外部事实。

## 四、正文编辑

每个主题按“结论句 → 子议题 → 证据/案例 → 管理含义 → 待确认”组织。

- 标题使用结论性名词短语，避免“关于某某的讨论”。
- `thesis` 是该议题最重要的判断，不重复标题。
- `claim` 必须能独立阅读；避免一个 bullet 塞入多个无关事实。
- 关键数字保留原值，并放进正文 `evidence`、决策依据、会议脉络或行动目标；不得单独制作数字看板。
- 有真实分歧时保留双方观点，不擅自调和。
- 激烈或口语化表述转换为正式语言，但不改变立场强度。

## 五、决策边界

只有明确同意、确定、批准、选择、停止、启动或等价确认的表达才能进入 `key_decisions`。

- “可以考虑”是建议。
- “倾向于，但还需评估”是待确认。
- “按这个节奏推”结合明确方案，可记录为决策。

每个决策保留依据和证据时间戳；无法确认责任人时写“待指定”。

## 六、待办

使用“责任人 + 动作 + 对象/范围 + 期限 + 验收标准”。不得只写“推进”“加强沟通”“持续关注”。

- 高：阻塞决策、明确紧急日期、关键风险或对外承诺。
- 中：已确认执行但不阻塞当前工作。
- 低：资料补充和非紧急优化。

## 七、成品质量门槛

- 顶部总结与正文不机械重复。
- 关键数字必须附着于会议结论、决策依据或行动目标，不单独构成指标看板。
- 决策、风险、待确认和行动项视觉上可区分。
- 正文同时保留结论和证据，不成为只有结论的薄摘要。
- 所有金额、比例、日期、数量、版本、组织名和产品名与原文一致。
